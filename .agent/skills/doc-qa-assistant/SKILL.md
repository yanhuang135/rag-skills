# 文档问答助手 (doc-qa-assistant)

## 功能介绍

文档问答助手是一个基于LangChain和FAISS的智能文档问答系统，能够：

- 自动扫描并处理knowledge目录下的PDF文档
- 使用主流免费开源Embedding模型将文档内容向量化
- 将向量存储到FAISS向量数据库中
- 使用主流免费开源大模型进行智能问答
- 支持基于文档内容的精确回答和上下文理解

## 技术架构

### 核心组件
1. **文档处理**：使用LangChain的PDFLoader处理PDF文档
2. **文本分割**：使用RecursiveCharacterTextSplitter进行文本分块
3. **向量嵌入**：使用主流免费开源Embedding模型
4. **向量存储**：使用FAISS向量数据库
5. **问答系统**：使用主流免费开源大模型，通过兼容OpenAI格式接入

### 技术栈
- Python 3.8+
- LangChain
- FAISS
- 开源Embedding模型（如BAAI/bge-base-zh）
- 开源大模型（如Llama 3、Claude等，通过OpenAI兼容接口）

## 使用方法

### 基本用法
1. **初始化系统**：首次使用时，系统会自动扫描knowledge目录下的PDF文档，处理并构建向量数据库
2. **提问**：直接向助手提问关于文档内容的问题
3. **获取回答**：助手会基于文档内容给出准确的回答，并提供引用来源

### 示例

**示例 1：查询特定文档内容**
```
问：2026年AI Agent技术有哪些关键发展趋势？
答：根据2026年AI Agent智能体技术发展报告，主要趋势包括...
```

**示例 2：跨文档查询**
```
问：人工智能在营销领域的应用趋势是什么？
答：根据中国AI+营销趋势洞察2026和2026年快消行业AI营销增长白皮书，主要趋势包括...
```

## 配置说明

### 环境变量配置

需要在系统中设置以下环境变量：

1. **EMBEDDING_MODEL**：Embedding模型名称或API地址
   - 默认：`BAAI/bge-base-zh`

2. **LLM_API_BASE**：大模型API基础地址（兼容OpenAI格式）
   - 例如：`https://dashscope.aliyuncs.com/compatible-mode/v1`（通义千问）

3. **LLM_API_KEY**：大模型API密钥
   - 对于通义千问API，需要在阿里云控制台获取

4. **LLM_MODEL**：大模型名称
   - 例如：`qwen-turbo`（通义千问）、`llama3`（Ollama）等

### 模型选择建议

#### 推荐的开源Embedding模型
- **BAAI/bge-base-zh**：中文语义理解能力强，性能平衡
- **BAAI/bge-small-zh**：轻量级，适合资源受限环境
- **sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2**：多语言支持

#### 推荐的大模型（通过OpenAI兼容接口）
- **通义千问API**：阿里云提供的免费开源大模型API，中文理解能力强
  - 模型：`qwen-turbo`
  - API地址：`https://dashscope.aliyuncs.com/compatible-mode/v1`
  - 获取API Key：
    1. 访问阿里云官网：https://www.aliyun.com/
    2. 登录或注册阿里云账号
    3. 进入"通义千问"服务页面
    4. 申请API Key并获取
    5. 将获取的API Key填入.env文件中的LLM_API_KEY字段
- **Llama 3**：Meta推出的最新开源大模型，性能优异（需本地部署）
- **Claude 3**：Anthropic的开源模型，上下文理解能力强
- **Gemini**：Google的开源模型，多模态能力突出

## 实现原理

### 文档处理流程
1. **文档扫描**：遍历knowledge目录下的PDF文件
2. **文本提取**：使用PDFLoader提取文档文本
3. **文本分割**：将长文本分割成合适大小的块
4. **向量嵌入**：使用Embedding模型将文本块向量化
5. **向量存储**：将向量存入FAISS索引

### 问答流程
1. **问题处理**：接收用户问题并向量化
2. **相似度搜索**：在FAISS中搜索最相关的文本块
3. **上下文构建**：将相关文本块组合成上下文
4. **生成回答**：将问题和上下文发送给大模型生成回答
5. **结果返回**：将回答和引用来源返回给用户

## 性能优化

1. **增量更新**：只处理新增或修改的文档
2. **缓存机制**：缓存向量数据库，避免重复处理
3. **批量处理**：批量处理文档，提高效率
4. **并行处理**：使用多线程或多进程加速处理

## 局限性

1. **文档格式**：目前仅支持PDF格式文档
2. **处理速度**：首次构建向量数据库可能需要较长时间
3. **模型依赖**：需要本地或远程部署相应的模型
4. **上下文长度**：受大模型上下文窗口限制

## 故障排查

### 常见问题

1. **无法找到PDF文档**
   - 检查knowledge目录是否存在
   - 确认PDF文件格式正确

2. **模型加载失败**
   - 检查环境变量配置
   - 确认模型API可访问

3. **回答质量不佳**
   - 尝试使用更强大的大模型
   - 检查文档内容是否完整

4. **处理速度慢**
   - 考虑使用轻量级Embedding模型
   - 增加系统资源（内存、CPU）
